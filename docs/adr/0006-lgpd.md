# ADR 0006 — Dados pessoais (LGPD)

**Status:** aceito

## Contexto
Os dados são públicos, mas citam pessoas. Juntar Diário, Receita, TSE e
folha num só lugar facilita montar perfil de pessoa física, que é o que a
LGPD pede para evitar (finalidade, necessidade, art. 6º). O plano de
fontes já decidiu que a folha com nome só vale para agentes políticos.

## Decisão
- **Agentes políticos** (prefeito, vice, secretários e vereadores) têm
  página, remuneração mês a mês e tudo o que se liga ao mandato.
- **Servidores e demais pessoas** aparecem no ato em que são citados, com
  o texto do ato. Não têm página, lista nem busca por pessoa. Folha só em
  agregados por órgão e cargo.
- **Sócio de empresa** aparece só dentro da página da empresa, com o CPF
  mascarado como a Receita publica.
- **Ligação por nome é sempre `fraca`** (ADR 0004) e é dita como
  "possível". O sistema nunca afirma que duas pessoas são a mesma.
- **API, MCP e dump seguem as mesmas regras.** A chave do MCP identifica
  o uso, não libera dado a mais. Nenhuma ferramenta devolve lista de
  pessoas físicas fora dos agentes políticos.
- **O que não guardamos:**
  - e-mail de quem assina alerta, além do necessário para o alerta;
  - argumentos das chamadas do MCP;
  - IP no banco: o limitador guarda o IP só em memória, por uma janela.
- **Correção:** qualquer pessoa pode reportar erro pelo site, e a
  correção vale para todas as portas.

## Consequências
- Algumas perguntas ficam sem resposta direta, como "em quais atos
  aparece fulano?" fora dos agentes políticos. A busca textual continua
  achando o nome no texto, como faria quem lesse o PDF, mas não existe
  perfil agregado.
- Cada fonte nova com dado pessoal passa por esta ADR antes de entrar.
